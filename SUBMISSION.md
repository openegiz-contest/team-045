## Mine

**Что моделируется.** Открытый карьер по добыче медно-порфировой руды с собственной
обогатительной фабрикой, карьер условный, параметры взяты по образцу казахстанских
порфировых месторождений (Бозшаколь, Актогай: среднее содержание 0,33–0,36 % Cu) и
паспортов техники. Пространство имён Ditto: `org.openegiz.sarybulak`, 62 двойника,
иерархия задана атрибутом `_parents` (видна в OpenEgiz → Twins).

**Объекты-двойники и связи** (определены в `team/mine/model.py`, параметры в `team/mine/config.py`):

| Двойник | Что хранит | Связи |
|---|---|---|
| `mine` | добыча руды и породы, коэффициент вскрыши, концентрат, медь, готовность парка, активные сценарии | корень иерархии |
| `bench-545`, `bench-530` → 30 `block-*` | блочная модель 25×25×15 м: координаты, содержание Cu, крепость (индекс Бонда), тоннаж; статус блока (в массиве → бурение → заряжен → взорван → отработка → отработан), остаток, гранулометрия P80 | блок → уступ → рудник; экскаватор ссылается на блок |
| `excavator-01/02` | состояние, текущий блок, содержание в забое, ковшей, очередь самосвалов, загрузка, наработка, здоровье | привязан к уступу и забою |
| `truck-01…06` | состояние, координаты x/y, дорога, назначение, груз, материал (руда/порода), содержание груза, скорость, топливо и расход, рейсы, наработка, здоровье, назначенный экскаватор | назначается диспетчером на экскаватор, едет по дорогам |
| `road-*` (8 участков) | узлы, длина, уклон, полилиния; статус open/closed, самосвалов на участке, проездов | граф дорог: забои → съезды → развязка → дробилка/склад/отвал/АЗС |
| `face-545`, `face-530`, `ramp-top`, `junction` | координаты, очереди | узлы графа |
| `crusher` | состояние, производительность, содержание питания (скользящий час), бункер, мощность, очередь | получает руду от самосвалов и со склада, отдаёт мельницам |
| `stockpile` | тонны, содержание, темп реклайма, очередь | буфер для шихтовки и на время простоя дробилки |
| `dump` (отвал), `fuel` (АЗС + мастерская) | тонны породы; выдано дизеля, очередь | |
| `plant` → `mill`, `flotation` | производительность, содержание питания, удельная энергия измельчения, мощность; извлечение, концентрат, хвосты | мельницы получают продукт дробилки |
| `substation` | нагрузка кВт и %, энергия, дизель парка, CO₂ | суммирует дробилку, мельницы, базовую нагрузку, дизель техники |
| `dispatcher` | назначения, средний цикл, среднее ожидание, режим шихтовки | |

**Как данные идут через платформу.** Симулятор `mine-sim` публикует по MQTT команды
`modify` протокола Ditto в `telemetry/<twin>` (как полевой шлюз), Ditto обновляет
двойники, Telegraf пишет события в InfluxDB, Grafana строит дашборды. Карта `mine-control`
читает двойники из Ditto (search API при старте, затем события Ditto из MQTT
`opentwins/twin/events/#`). Сценарии с карты уходят в MQTT `sarybulak/commands`, их
последствия видны через те же двойники. Ядро платформы не изменено; добавлены overlay
`team/compose.yml` и цели `make mine`, `make mine-stop`, `make mine-check`.

## Modules and What-if Scenarios

Все модули работают на стенде одновременно; таблица говорит, где именно их увидеть.
Карта: http://localhost:8095/ ; дашборды: Grafana → папка **Sarybulak Mine**.

| Модуль / сценарий | Что делает | Как увидеть на стенде | Как отменить |
|---|---|---|---|
| **01 Транспорт и диспетчеризация** | Дискретная симуляция цикла самосвала (подъезд, погрузка ковшами, гружёный рейс по графу дорог с учётом уклонов, очереди у дробилки/склада/отвала, разгрузка, порожний рейс, заправка). Диспетчер назначает порожний самосвал экскаватору с минимальным ожидаемым временем (время в пути + очередь × время погрузки), с поправкой на шихтовку. Маршрут по Дейкстре по открытым дорогам, объезд при закрытии | Карта: самосвалы движутся по дорогам, цвет кузова = материал, подпись = состояние и груз; очереди у забоев. Дашборд «транспорт и диспетчеризация»: таблица парка, скорости, груз, рейсы, трафик по дорогам. `dispatcher.assignments`, `avg_cycle_min`, `avg_queue_min` | — |
| **02 Геология и качество руды** | Блочная модель с содержанием Cu и крепостью; рудоконтроль: груз ≥ борта (0,25 % Cu) → дробилка, иначе → отвал; шихтовка: содержание питания держится в коридоре 0,34–0,50 % Cu за счёт выбора забоя, отвода богатых рейсов на склад и реклайма со склада; реклайм также спасает голодающую дробилку | Карта: цвет блоков = содержание, серые = порода, белая рамка = отрабатываемый блок; склад показывает тонны, содержание и реклайм. Обзор: «питание фабрики», «содержание в забоях», «рудный склад»; `dispatcher.blend_mode` | — |
| **03 Буровзрывные работы** | Бригада БВР держит два взорванных блока впереди экскаватора: бурение 9 ч, заряжание 3 ч, взрыв; гранулометрия P80 растёт с крепостью; крупный кусок замедляет погрузку и снижает производительность дробилки | Карта: штриховка = бурение, точки = заряжен, пунктирная рамка = взорван; журнал событий «Взрыв блока … P80»; `block.fragmentation_p80_mm`, `crusher.throughput` | — |
| **06 Переработка** | Дробилка с бункером, мельницы (SAG + шаровая) с удельной энергией по закону Бонда от крепости руды, флотация: извлечение падает при бедном питании и твёрдой руде, концентрат 24 % Cu | Карта: фабрика показывает т/ч, МВт, извлечение, концентрат. Дашборд «фабрика и энергетика» | — |
| **05 Энергетика** | Мощность дробилки и мельниц из закона Бонда + базовая нагрузка; дизель самосвалов по режимам (гружёный / порожний / холостой / погрузка) и экскаваторов; энергия, дизель и CO₂ нарастающим итогом | Карта: подстанция (МВт, %), АЗС. Дашборд «фабрика и энергетика»: мощность, дизель по самосвалам, CO₂ | — |
| **07 ТО и надёжность** | Случайные отказы самосвалов и экскаваторов (экспоненциально по наработке, вероятность растёт с износом), ремонт по MTTR; плановое ТО через 250 ч (самосвалы, в мастерской у АЗС) и 500 ч (экскаваторы); готовность парка | Карта: красная техника = ремонт/ТО; журнал событий. Обзор: «готовность парка»; дашборд «транспорт»: техническое состояние, %; `truck.health_pct`, `hours` | — |
| Сценарий **отказ экскаватора ЭКГ-1 / ЭКГ-2** | Экскаватор выводится из строя: самосвалы в очереди и в пути переназначаются на другой, очередь там растёт, добыча падает, при отказе единственного рудного забоя фабрика питается со склада | Кнопка на карте; экскаватор краснеет, самосвалы разворачиваются; обзор: очереди, дробилка | Повторное нажатие или «Сбросить все сценарии» |
| Сценарий **остановка дробилки** | Самосвалы с рудой, включая те, что уже едут, перенаправляются на рудный склад; фабрика останавливается, нагрузка подстанции падает до базовой; после запуска склад снова питает дробилку | Кнопка; дробилка красная, склад растёт, «нагрузка» падает с ~13,5 до ~2,7 МВт | Повторное нажатие |
| Сценарий **закрыть западный съезд** | Участок `road-ramp-west` закрыт: самосвалы с уступа 545 идут объездом через уступ 530 и восточный съезд; цикл и расход топлива растут | Кнопка; дорога красная пунктиром, маршруты меняются; `avg_cycle_min`, `fuel_rate` | Повторное нажатие |
| Сценарий **закрыть главную дорогу** | Объезда нет: гружёные самосвалы останавливаются (`blocked`), дробилка живёт на складе, затем голодает | Кнопка; дорога красная, самосвалы стоят | Повторное нажатие |
| Сценарий **парк 4 или 3 самосвала** | Лишние самосвалы паркуются у АЗС: экскаваторы ждут, производительность падает, очереди исчезают | Кнопка; припаркованные полупрозрачны; `trucks_active` | Повторное нажатие (вернуть 6) |
| Сценарий **бортовое содержание 0,45 % / 0,15 %** | Переклассификация блоков руда/порода на лету: при высоком борте растёт вскрыша и содержание питания, тонн руды меньше; при низком — питание беднеет, извлечение падает | Кнопка; блоки перекрашиваются, `strip_ratio`, `feed_grade`, `recovery` | Повторное нажатие (вернуть 0,25) |

Команды сценариев принимаются и по HTTP: `POST http://localhost:8095/api/command`
(`{"action":"crusher_down","on":true}` и т. д.), что использует `make mine-check`.

## What works and what does not

Проверено на стенде (`make mine-check` проходит): создание двойников, телеметрия всех
двойников, история в InfluxDB, четыре дашборда, карта, все сценарии и их отмена, сброс.
Длительный прогон симулятора: 300 ч модельного времени без остановок.

Известные ограничения:
- блочная модель конечна: 30 блоков отрабатываются примерно за 350 ч модельного времени
  (35 ч на стенде при ускорении 10×), после чего экскаваторы переходят в `no_block`;
- дорожная сеть не моделирует встречный трафик и обгоны; самосвалы не сталкиваются;
- фабрика описана в сосредоточенных параметрах (один поток, без контуров классификации);
- зимних условий, осадков и состояния дорог нет.

## Mine visualization

**Карта карьера** http://localhost:8095/ (также внутри Grafana: дашборд «Sarybulak: карта
карьера»). Живая 2D-схема, целиком построенная из двойников: уступы и блоки (цвет =
содержание, штриховка = стадия БВР, рамка = отработка), дороги (красный пунктир = закрыта),
самосвалы с анимацией движения по координатам из Ditto, экскаваторы, дробилка с уровнем
бункера, склад, отвал, АЗС, фабрика, подстанция. Наведение на любой объект показывает все
его features. Справа: показатели смены, кнопки сценариев, журнал событий. Колёсико мыши
и перетаскивание — масштаб и панорама; кнопки «карьер / фабрика / весь».

**Дашборды Grafana** (папка *Sarybulak Mine*): «обзор карьера», «транспорт и
диспетчеризация», «фабрика и энергетика», «карта карьера». Данные из InfluxDB через
штатный конвейер платформы.

## Limitations

См. раздел «What works and what does not». 3D-сцены нет: выбрана 2D-карта, которая работает
в окружении судьи без GPU и без внешних ресурсов (страница не загружает ничего извне).
