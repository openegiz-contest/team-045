# team/ — цифровой двойник горизонта ВЖР

Код команды ML. Решение построено на OpenEgiz v1.0.4 без изменения ядра платформы: всё, что
здесь лежит, подключается к стеку overlay-файлом `compose.yml` командой `make mine`.

```text
team/
├── compose.yml              overlay: mine-setup, mine-sim, mine-control, дашборды Grafana
├── Dockerfile, requirements.txt
├── mine/
│   ├── config.py            рудник, система разработки, нормы воздуха, целики, сейсмика,
│   │                        техника, план горизонта — каждое число с источником
│   ├── model.py             166 двойников Ditto (атрибуты = геометрия, паспорта, нормы)
│   ├── setup_twins.py       PUT двойников в Ditto (идемпотентно)
│   ├── sim.py               симулятор: сеть Харди–Кросса, газы, целики, сейсмика, цикл камер,
│   │                        наряд и вердикты, люди, техника, руда; команды сценариев
│   ├── run_sim.py           MQTT: telemetry/<twin> (Ditto protocol), zhezkazgan/commands, zhezkazgan/events
│   └── control.py           план горизонта и панель наряда/сценариев (HTTP :8095), данные из Ditto
├── static/index.html        живой 2D-план (SVG), строится из атрибутов и features двойников
├── grafana/                 build_dashboards.py → dashboards/*.json, provisioning/
├── scripts/                 urls.sh, check.sh (сквозная проверка), dev_preview.py (без платформы)
└── data/seismic-bumps/      seismic-bumps.arff (UCI, CC BY 4.0) — калибровка сейсмичности
```

## Поток данных

```text
mine-sim ──MQTT telemetry/<twin> (Ditto protocol modify)──▶ Ditto (состояние двойников)
                                                               │
          Ditto ──MQTT opentwins/twin/events/…──▶ Telegraf ──▶ InfluxDB ──▶ Grafana (дашборды)
                                  │
                                  └──▶ mine-control (кэш состояния) ──HTTP /api/state──▶ план (браузер)

план ──POST /api/command──▶ mine-control ──MQTT zhezkazgan/commands──▶ mine-sim (наряд, сценарий)
```

План и дашборды получают данные только из платформы: при старте `mine-control` читает все
двойники пространства имён `org.openegiz.zhezkazgan` через Ditto search API, затем следит за
событиями изменения, которые Ditto публикует в MQTT (`opentwins/twin/events/#`). Симулятор не
обращается ни к Ditto, ни к InfluxDB напрямую. Он публикует только изменившиеся двойники и раз в
минуту полный снимок.

## Модель в двух словах

- **Вентиляция.** Сеть из 18 выработок и 3 стволов; сопротивление Аткинсона R = α·P·L/A³;
  ВГП с характеристикой p = p₀(1 − (Q/Qmax)²); распределение по контурам методом Харди–Кросса
  (остовное дерево по наименьшим сопротивлениям, двери и завалы в хордах). Газы и тепло
  переносятся по струе смешением в узлах. Камеры панели делят её расход; потребность — нормы РК.
- **Целики.** Хедли–Грант S = K·w^0,5/h^0,75 против σ = ρgH/(1−e); высота целика растёт со
  слоями, извлечение растёт с отработкой соседей и выемкой целиков; повреждение от толчков.
- **Сейсмика.** Толчки за смену по частотам seismic-bumps; большой толчок — вывод людей на 2 ч.
- **Наряд.** Вердикт по камере: запрещено (нет пути к стволу, критический целик, конвергенция,
  ПДК, температура, нет струи, нет воздуха на звено, проветривание после взрыва) / ограничено
  (воздуха нет на ПДМ; целик под наблюдением или сейсмика: без новых взрывов) / разрешено.
  Автонаряд и ручной наряд мастера с отклонением недопустимых назначений.

## Команды сценариев (`POST /api/command`)

| action | параметры | что делает |
|---|---|---|
| `fan` | `speed_pct` | обороты ВГП, 0 = остановка |
| `door` | `target` (aw-door-3), `on` | открыть/закрыть вентиляционную дверь |
| `regulator` | `target` (aw-p1-vent…), `closed_pct` | прикрыть регулятор панели |
| `blocked` | `target` (aw-…), `on` | завал выработки |
| `extra_diesel` | `target` (panel-…), `kw`, `on` | дополнительная дизельная техника в панели |
| `seismic` | `target`, `energy` | сейсмический толчок |
| `pillar_extract` | `target` (c1-24…), `on` | выемка целика |
| `aux_fan_fail` | `target` (k1-26…), `on` | отказ ВМП камеры |
| `assign` | `crew`, `chamber` (или null) | наряд мастера |
| `auto_plan` | `on` | автонаряд |
| `reset` | — | сброс всех сценариев |

## Разработка

```bash
make mine            # поднять платформу и рудник
make mine-check      # сквозная проверка
make logs S=mine-sim # журнал симулятора
python3 team/grafana/build_dashboards.py   # пересобрать дашборды после правки
python3 team/scripts/dev_preview.py        # план без платформы (только для разработки)
```
